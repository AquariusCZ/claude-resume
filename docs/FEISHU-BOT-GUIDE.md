# 飞书机器人使用速查

切换到 cc-connect 之后，机器人的交互方式变了：**没有底部菜单按钮，改用斜杠命令**，
但大部分命令会回一张**带按钮的卡片**，点着用就行，不用背。

> 旧系统留下的底部三个菜单按钮（主菜单 / 闲聊 / 模型）**已在飞书开放平台删除**
> （2026-08-06 实测确认），界面里不再出现。删除原因留档：cc-connect 虽支持飞书菜单，
> 但菜单事件结构上不带 chat_id，拿 open_id 当 receive_id 发回复会被拒
> （`230001 invalid receive_id`）——按钮触发得了、回复送不到。

## 最常用的四条

| 想干什么 | 发什么 | 说明 |
|---|---|---|
| **看所有命令** | `/help` | 回一张分类卡片，每条命令右边有 ▶ 可直接点 |
| **换模型** | `/model` | 回一张下拉卡片，选完即生效 |
| **换服务商**（换成 DeepSeek 等） | `/provider` | 模型和服务商是两层，见下 |
| **换项目目录** | `/dir <路径>` | 决定 AI 在哪个目录里干活 |

## 模型 vs 服务商：两层，别搞混

- **`/model`** 换的是**当前服务商内部**的模型。用 Claude 订阅时，这里只有
  `sonnet` / `opus` / `opus[1m]` / `haiku`。
- **`/provider`** 换的是**整套 API 接入**。DeepSeek 是独立端点 + 独立 key，
  属于这一层，所以**不会出现在 `/model` 的下拉里**。

```
/provider list             看有哪些服务商
/provider switch deepseek  切到 DeepSeek
/model                     切完再看，列表会变成该服务商的模型
```

**怎么确认切成功**：看回复末尾那行页脚，比如
`deepseek-chat · out 283 · in 2 · ctx 23%` —— 它是本次回复**实际用的模型**和 token 消耗，
比任何提示都准。

## 项目与目录

cc-connect 这边只有**一个项目**，靠切工作目录来访问不同代码库：

```
/dir                              看当前目录和最近用过的
/dir C:\Users\你\Desktop\某项目    切过去
/dir 2                            按历史序号切
/dir -                            切回上一个
```

> **为什么只有一个项目**：同一个飞书应用绑多个项目时，一条消息会被每个项目
> 各收一次、各起一个 agent（实测 9 个项目 = 9 个 claude 进程、9 条回复、额度烧穿）。
> 上游的多项目用法是「每个项目配不同平台」，不是「多个项目共用一个飞书应用」。

**注意**：`/dir` 是特权命令，需要配置 `admin_from`（已配好，锁定在 owner）。

## 会话管理

一个会话会累积上下文。**换话题时开新会话**，否则新问题会接着旧任务跑
（实测：旧会话里有找文件的任务，发「你好」它继续去找文件）。

```
/new [名字]     开新会话
/list           列出所有会话
/switch <序号>  切换
/current        看当前是哪个
/history [n]    看最近 n 条
/stop           停止当前执行
```

## 显示模式

工具调用卡片（`Tool #1: Bash …`）可以关掉，在 `~/.cc-connect/config.toml`：

```toml
[display]
mode = "compact"   # full=显示思考与工具调用 / compact=只留正文分条 / quiet=正文合一张卡
```

改完要重启 cc-connect。

## 权限

只有 `allow_from` 里的 open_id 能用这个机器人，其他人发消息**不会有任何响应**。
`admin_from` 里的人才能用 `/dir`、`/shell` 等特权命令。两者都锁定在 owner。
