# S10-G 规格:cc-connect 配置合并写入的测试

产出**一个文件**:`csharp/test/AiResume.Tests/CcConnectConfigPreserveTests.cs`(xUnit,C#/.NET 10)。
只写测试,不改实现。中文注释。

## 1. 被测行为

`CcConnectConfigGenerator.Write(path, config)` 现在是**合并写入**而不是整份覆盖:

- 目标文件已存在时,原样保留除 `[[projects]]` 及其子表(`[projects.*]` / `[[projects.*]]`)之外的**全部内容**;
- 然后在末尾追加本次生成的 `[[projects]]` 段;
- 目标文件不存在时,行为不变(只写生成内容)。

`internal static string ExtractNonProjectSections(string existingToml)` 是其核心,
测试项目已通过 InternalsVisibleTo 可见;若不可见则只经 `Write` 间接验证(优先直接测)。

**为什么要有这个行为**(写进测试注释,别丢):2026-08-06 生产切换时,原实现整份覆盖,
把用户已启用的 `[management]` 段(`http://localhost:9820` 的 Web 管理台)一并抹掉,
admin 页直接打不开。这份配置不归我们独占——我们只拥有项目清单那一部分。

## 2. 隐含前置(照抄否则失败)

- `CcConnectConfig(IReadOnlyList<CcConnectProject> Projects, CcConnectPlatformOptions Feishu)`;
- `CcConnectPlatformOptions(string AppId, string AppSecret, string AllowFrom)` —— **三个参数,AllowFrom 必填且不得为空**,
  空值会让 `Validate` 抛 `ArgumentException`;
- `CcConnectProject(string Name, string Agent, string WorkDir, string Mode = "default", string AdminFrom = "")`;
- 生成的项目段形状是**嵌套表**:`[[projects]]` → `[projects.agent]` → `[projects.agent.options]` →
  `[[projects.platforms]]` → `[projects.platforms.options]`;`admin_from` 在 `[[projects]]` 层,
  `allow_from` 在 `[projects.platforms.options]` 层;
- 生成内容首行是 `# Generated by AiResume.Wrapper (S6-A). Deterministic; do not edit by hand.`;
- 所有临时文件落 `Path.GetTempPath()` 下的 GUID 目录,`IDisposable` 里递归删除并吞异常;
- **绝不触碰真实 `~/.cc-connect/`**。

## 3. 必须覆盖的用例

1. `保留management段` —— 先写一份含 `[management]\nenabled = true\nport = 9820\ntoken = "T"` 的文件,
   再 `Write`,断言结果**仍含**这三行,且含 `[[projects]]`。
2. `保留顶层键与注释` —— 旧文件含 `# 我的注释` 与顶层 `data_dir = "x"`(在任何表头之前),
   断言二者都还在。**注释必须逐字保留**(实现刻意做行级切分而非解析后重序列化)。
3. `保留projects之后出现的段` —— 旧文件顺序是 `[[projects]]` 在前、`[log]` 在后,
   断言 `[log]` 被保留(证明剔除逻辑在遇到下一个非 projects 表头时正确退出项目区域)。
4. `旧的projects段被剔除不残留` —— 旧文件含 `[[projects]]` + `name = "OLD"` +
   `[projects.agent]`,新配置只有 `NEW` 项目;断言结果**不含** `"OLD"`,
   且 `[[projects]]` 只出现新配置的个数。
5. `旧的projects子表也被剔除` —— 旧文件含 `[projects.agent.options]` 与
   `[[projects.platforms]]`;断言这些旧内容(用一个独特标记串如 `work_dir = "C:\\OLD"`)不残留。
6. `重复写入不累积` —— 连续 `Write` 三次,断言 `[[projects]]` 数量恒等于项目数、
   `[management]` 只出现一次、生成标记行只出现一次。
7. `目标文件不存在时行为不变` —— 空目录直写,断言内容等于 `Render(config)`。
8. `旧文件为空或全空白` —— 断言不抛异常,结果含 `[[projects]]`。
9. `写入是原子的且不留 tmp` —— `Write` 后断言目录下没有 `*.tmp-*` 残留。
10. `allow_from为空时拒绝写入` —— 构造 `AllowFrom: ""`,断言抛 `ArgumentException`,
    **且目标文件保持原内容不变**(fail-closed 不能写半截)。

## 4. 约束
