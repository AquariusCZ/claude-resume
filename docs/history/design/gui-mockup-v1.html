设计说明

立论。这个产品的本质是等待与调度——额度像潮水退去又回来，引擎在岸边值守。所以主视觉不是又一个进度条，而是「额度潮汐轴」：它同时回答三个问题——窗口在哪、还剩多少、什么时候回来。这是 cc-connect 和其他 AI 工具都没有的东西，也正是本产品唯一不可替代的能力（ADR-0003 §1 实证 4）。

配色。深海青黑基底（#0E1A1F）而非纯黑，避开「近黑 + 单一荧光色」的通用观感；--tide 青绿代表可用与运行，--ebb 琥珀代表消耗与等待——两色互为潮汐两端，语义闭环，不是随意取的强调色。现役 GUI 的高饱和橙主按钮已移除。

字体分工。所有数据（时间、路径、百分比、时长、序号）走等宽，所有叙述走比例字体。这条规则贯穿全局，让「机器事实」和「人类说明」一眼可分——这是开发者工具应有的身份，也顺带解决现役中文字重层级扁平的问题。

队列序号。1 2 3 编码的是真实执行顺序（续跑确实按序进行），不是装饰性编号；已完成项换成对勾并退出编号序列，队列因此始终可读作「接下来会发生什么」。

密度。项目行高从现役的约 62px 压到 40px，7 个项目无需滚动即可全见；腾出的纵向空间给了潮汐轴和状态面板。日志默认折叠为单行，只显示最后一条——它平时不重要，出事时才展开。

与性能的关系。视觉之外的硬指标：首帧渲染不得依赖项目发现与健康探测（现役实测冷启动 3701ms，主因是 UI 线程同步 I/O）。上图所有「状态值」都应以骨架先出、异步填充，任何技术栈都必须遵守这一条。
